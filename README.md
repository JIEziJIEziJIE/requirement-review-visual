# 需求审查可视化版 · 使用说明

> 两级门禁需求审查：一级快筛 8 项标准出**达标卡**，二级深审 12 个可测性维度出**雷达图**。
> 每次执行都双交付——**Markdown 报告**（能编辑、能转发）+ **HTML 可视化**（能展示、能打印、断网能开）。

- 版本：2.3.2 ｜ 作者：杰子 ｜ SkillHub slug：`requirement-review-visual`
- 面向 AI 的执行规则在 `SKILL.md`；**本文件面向人**，讲怎么装、怎么用、怎么改模板。

---

## 1. 它能干什么

| | 一级：快筛门禁 | 二级：深审门禁 |
|---|---|---|
| 回答什么 | 这份需求达不达标、能不能进下一阶段 | 缺口落在哪些可测性维度、对用例/验收/回归有什么影响 |
| 检查项 | 8 项最小标准 | 12 个可测性维度 |
| 结论 | 产品自检 / 开发快评 / 测试快评 三链路固定结论 | 建议 NNN + 维度成熟度评分 + 综合指数 |
| 可视化 | 8 项达标卡 HTML | 12 维雷达图 HTML |
| 什么时候用 | **默认先跑这个** | 一级出现 P0 未闭环，或明确要求"详细审查 / 完整评审 / 出完整可测性报告" |

8 项最小标准：目标范围 / 主流程 / 业务规则 / 权限前置 / 异常边界 / 状态一致 / 依赖交付 / 验收证据。

三条链路按**本轮问题**自动路由：

| 你的问题 | 走的链路 | 结论词三选一 |
|---|---|---|
| 需求写全了吗、能不能提交评审 | 产品自检 | 可提交评审 / 建议补充后提交 / 暂不建议提交 |
| 能不能开工、实现方案明确吗 | 开发快评 | 可以进入开发 / 补充确认后可以开发 / 暂不建议直接开发 |
| 能不能测、测试范围怎么定 | 测试快评 | 具备初步可测条件 / 补充确认后可测 / 暂不具备初步可测条件 |

> ⚠️ 路由只看你**这一轮说了什么**，不会因为你职业是测试就默认走测试链路。没说目标时会先问一个最小问题。

## 2. 安装

### 方式 A：本地目录（最快）

把整个 `requirement-review-visual/` 目录放到 `~/.workbuddy/skills/` 下即可：

```
C:\Users\<你>\.workbuddy\skills\requirement-review-visual\
```

重启会话或重新加载技能列表后生效。

### 方式 B：从 SkillHub 安装

```bash
# 需已登录（token 形如 skh_xxx，在 SkillHub 个人控制台创建）
python ~/.skillhub/skills_store_cli.py install requirement-review-visual
```

## 3. 怎么用

### 怎么把它叫出来

**不用记命令**，在对话里直接说就行。三种叫法任选：

| 叫法 | 示例 |
|---|---|
| 说需求 + 目标 | 帮我看看这份需求能不能测：`E:\需求\XX方案.docx` |
| 点名调用（多个技能都匹配时用它锁定） | 用 requirement-review-visual 审查《XX方案》，判断能不能提交评审 |
| 先给材料再下指令 | （上传文件或粘贴正文后）这份需求做完整可测性深审，出雷达图 |

**调用后会经历什么**：① 它确认材料来源与读取情况；② 你没说审查目标时会问 A/B/C/D，回一个字母即可；③ 输出结论 → 落盘两份文件到桌面 → 给出路径。

**没被叫出来怎么办**：确认技能目录在 `~/.workbuddy/skills/requirement-review-visual/` 且会话已重启；或改用"点名调用"锁定。

### 最简用法

> 审查一下这份需求：`E:\xxx\活动方案.docx`

或：

> 用 ima 知识库里的《XX 活动方案》做需求审查，判断能不能提交评审。

### 指定门禁与链路

| 说法 | 效果 |
|---|---|
| "帮我看看需求能不能测" | 一级 · 测试快评 |
| "这份需求能开工吗" | 一级 · 开发快评 |
| "需求写全了吗、能过评审吗" | 一级 · 产品自检 |
| "做完整可测性深审 / 出雷达图" | 二级 · 12 维深审 |

把文件路径或知识库文档名接在后面即可，例如「审查这份需求能不能开工：`E:\xxx\活动方案.docx`」。

### 可选参数（不写就自动判断）

| 参数 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `depth` | `1` / `2` | 自动 | 指定门禁：1 快筛、2 深审 |
| `lane` | `product` / `dev` / `test` | 自动 | 指定链路 |
| `out` | 目录路径 | 桌面 | 报告落盘目录 |
| `format` | `md+html` / `md` / `html` | `md+html` | 交付物组合 |
| `top` | 数字 | 8 | 待确认事项条数上限 |
| `lang` | `zh` / `en` | `zh` | 报告语言 |

三种写法都认：`key=value`（`depth=2 out=E:\reports`）、`--flag`（`--no-html`）、自然语言（"只出 Markdown""报告放 D 盘"）。写错的参数会被忽略并提示可用项，不会中断执行。

### 出错了会怎样

不会崩，也不会静默跳过。每类异常都给一段结构化提示：

```
[ERR-MAT-01] 《XX方案》未能读到正文（知识库返回文件获取失败，已重试 2 次）
  · 已按规则处理：在材料表标注读取状态，就已读部分出结论，未读部分不猜测
  · 建议你：从知识库导出后给我文件路径，或直接粘贴正文
```

固定三段：**发生了什么 / 我怎么兜底的 / 你下一步做什么**。多个异常会在报告末尾集中列出，不会逐条打断。完整 12 条错误码见 `references/error-codes.md`。

### 支持的材料来源

本地文件（DOC/DOCX/WPS/PDF/PPT/XLS/CSV/TXT/MD/HTML/JSON/图片/压缩包）、在线文档与网页、知识库（ima 等）、原型链接、企微/语雀/腾讯文档、截图 OCR、录屏关键帧、直接粘贴文本。

## 4. 输出物

落盘到桌面（`E:\OneDrive\Desktop`）：

| 门禁 | Markdown 报告 | HTML 可视化 |
|---|---|---|
| 一级 | `｛需求名｝-快筛-｛YYYYMMDD｝.md` | `｛需求名｝-快筛达标卡-｛YYYYMMDD｝.html` |
| 二级 | `需求可测性审查_｛简称｝_｛YYYYMMDD｝.md` | `｛需求名｝-可测性雷达图-｛YYYYMMDD｝.html` |

报告里能直接用的部分：

- **材料范围与读取状态** —— 每份材料的来源与是否读成功；
- **待确认事项** —— 打 P0/P1/P2，是报告的核心；
- **可转发问题清单**（一级）/ **建议 NNN**（二级）—— 复制到企微直接发给产品。

> 二级报告的措辞经过约束：不会出现"问题清单""严重等级""不合格""谁漏了"这类评价性表述，方便直接转给需求方。

## 6. 改模板（可视化产物）

两个 HTML 都是**零外部依赖**：不引 CDN、不引字体、不引图表库（雷达图坐标由内联脚本算 SVG），断网可开、A4 打印友好、浅色底深色字。

改法：**只改文件顶部 `<script>` 里的 `DATA` 区**，其余结构与样式不要动。模板会在渲染时自动对动态文本做安全转义，调用方式和填写方式不变，不需要用户增加任何操作。

`fast-screen-card.html` 的 DATA 区：

```js
const DATA = {
  title: "需求名",
  verdict: "建议补充后提交",        // 只写实际结论，不要并列候选
  rate: "1/8",                      // 达标率 = 已明确 ÷ 计入项
  counts: { ok:1, partial:4, miss:3, na:0 },
  items: [
    { no:1, name:"目标范围", status:"已明确",  desc:"..." },
    ...
  ],
  todos: [ { level:"P0", text:"..." } ]
};
```

`deep-review-radar.html` 的 DATA 区：

```js
const DATA = {
  title: "需求名",
  index: 70,                        // 综合指数
  dims: [
    { short:"目标范围", name:"目标、范围与成功标准", value:100, status:"已明确", note:"" },
    { short:"兼容非功能", name:"兼容性与非功能要求", value:null, status:"不适用", note:"本期不涉及" }
  ],
  priorities: { p0:1, p1:4, p2:2, p3:1 },
  todos: [ ... ]
};
```

状态色四档固定：已明确 `#1D9E75` / 部分明确 `#BA7517` / 未明确 `#E24B4A` / 不适用 `#888780`。

维度成熟度映射：**已明确 100 ｜ 基本明确 75 ｜ 部分明确 45 ｜ 未明确 15 ｜ 不适用不计入均值**。

## 7. 常见问题

**Q：为什么它问我"本次想判断什么"？**
材料给了但没说目标，无法决定走哪条链路。回答 A/B/C/D 即可（可多选）。

**Q：报告里"未明确"很多，是需求写得差吗？**
不一定。先核对"材料范围与读取状态"——如果文档没读全，缺的部分会如实归入未明确，而不会凭标题猜测。

**Q：一级过了会自动出二级报告吗？**
不会。一级无 P0 且你没要求深审时不输出二级，避免冗余。

**Q：能不能改结论措辞？**
三链路结论词和二级三档结论是固定的，不允许自造——这是为了保证同一份需求在不同时间审查结论可比。报告正文的措辞可以随便改。

**Q：HTML 打不开/显示异常？**
检查是否误改了 `DATA` 区以外的内容。模板自带示例数据可原样打开验证。
