## 1. 速查表（16 条）

| # | 坑 | 为什么错 | 正确做法 |
|---|---|---|---|
| 1 | 用用户职业背景（如测试）默认走测试链路 | 违反本轮问题优先原则，用户可能这次想问能否开工 | 只看本轮问题；无目标就问最小问题 |
| 2 | 把"待确认"写成"已明确"，或自己编个值填上 | 制造虚假确定性，后续用例断言全错 | 保留待确认，落成 Q 编号问题 |
| 3 | 输出"已明确 / 部分明确 / 未明确"选项串 | 用户无法直接使用，等于没结论 | 只写实际那一档 |
| 4 | 为凑数量编建议 | 稀释真正的风险 | 无缺口就写"未发现需要补充之处" |
| 5 | 把"推断"写成既定规则 | 推断不是事实 | 标注"推断"，且不作为最终断言 |
| 6 | 雷达图把"不适用"按 0 计入均值 | 指数被拉低，结论失真 | 排除，并在图、表两处标注 |
| 7 | Markdown 改了结论，HTML 没同步 | 两处矛盾，可信度归零 | 同源填写，落盘前对照 |
| 8 | 一级过了就顺手输出二级报告 | 违背两级门禁的分层设计 | 无论是否有 P0，未明确要求深审不自动输出；可提出建议 |
| 9 | "可提交评审"直接推导出"可以开发" | 三类结论不可互推 | 分别判断，分别给结论 |
| 10 | 把"材料没写"说成"系统不支持" | 无证据的否定判断 | 写"暂未提供"，列入待确认 |
| 11 | 材料读取失败还照常出结论 | 结论建立在空材料上 | 全不可读停止正常评分；部分可读需 coverage 和开头局部限定，不能全文背书 |
| 12 | 多份材料冲突时自己选一版 | 越权拍板 | 提出"以哪一版为准"的确认建议 |
| 13 | 截图/OCR 模糊还去猜字段与数值 | 猜错代价高 | 一律标"待确认" |
| 14 | 二级用了"问题清单""严重等级" | 措辞会引发对抗 | 用"建议 NNN"和"优先级" |
| 15 | 把测试侧建议写成产品最终方案 | 越界 | 写"建议明确……"，留待产品确认 |
| 16 | 报告写得很长但没有结论 | 用户拿不到可行动项 | 结论前置，每条建议带影响与确认对象 |

## 2. 正反例对照

### 2.1 结论表达

**反例**
> 该项结论为：已明确 / 部分明确 / 未明确 / 不适用。

**正例**
> 未明确。材料仅写"需登录"，未说明新用户、老用户与 VIP 的可见范围差异。

### 2.2 待确认 vs 编造

**反例**
> 优惠券有效期为 7 天，过期自动作废。

**正例**
> 材料未说明优惠券有效期与过期处理，建议明确有效期起止时刻、过期提示与是否支持补发。（待确认 · 产品）

### 2.3 推断标注：被审查业务不等于本技能

以下只审查虚构业务的重试机制，不是授权本技能失败后重试。

**反例**
> 预约通知发送失败会自动重试三次。

**正例**
> 推断：预约通知可能存在重试机制（依据：业务接口文档出现 retry 字段），但材料未给出重试次数与超时兜底，建议明确。（推断，不作断言）

“不自动修复/自动重试”约束本技能读取、生成和写入的失败处理，不应删掉业务审查中的重试、恢复、防重复与状态一致性维度。

### 2.4 冲突处理

**反例**
> 活动时间以原型为准，为 9 月 1 日至 9 月 10 日。

**正例**
> PRD 第 3 章写"活动周期为 9 月 1 日—9 月 15 日"，原型"活动时间"区域标注"9/1—9/10"，两处口径不一致，建议确认以哪一版为准，并同步到运营配置与验收样例。

### 2.5 缺失处理

**反例**
> 系统不支持批量导入。

**正例**
> 材料未说明是否支持批量导入及单次上限，建议明确。（当前按"暂未提供"处理，不作"不支持"结论）

### 2.6 建议 vs 方案

**反例**
> 应将重复领取限制为每人每天 1 次。

**正例**
> 建议明确重复领取的限制维度（按人/按天/按活动）、次数上限，以及超限时的提示与拦截位置。

## 3. 常见的“看似对其实错”

1. **把所有维度都判成"部分明确"以求稳妥** —— 稳妥不等于模糊。材料真的写清楚了就给"已明确"，否则雷达图全是 45 分，指数永远 45，结论失去区分度。
2. **为了显示上限删 P0** —— 按真实影响判断，不因超过 5 项就降级或删除；首屏重点上限只影响展示，完整事项保留并参与统计。
3. **指数和结论各算各的** —— 深审有开放 P0 就第三档，高均分也不能抹掉 P1；一级产品填口径 P0 可为“建议补充后提交”，不能跨链路套用。
4. **翻译术语却仍让产品选实现方案** —— 产品回答业务结果，研发确认实现，不只是给“幂等”补个定义。
5. **收到产品回复就关闭整个事项** —— 所需研发分支未确认就继续开放；重判受影响维度，别只改显示数字。
6. **补文档等于已验证** —— 确认、生成、写入、验证分别记；写后需保存读回，功能验证需实际执行证据。
7. **把 Markdown 作为永远正确的真源** —— 检出不一致先停止相关交付，核对材料、DATA 与版本；确认原因及新的操作授权后才处理，不自动修复、不选一份盲从。
8. **旧示例分数复制到新模板** —— schemaVersion=2 禁手填派生数字；v2.4.0 合法完整数据仍可用，宽松非法字段或非全文缺 coverage 需按原材料确认，不能自动迁移猜值。

## 4. v2.4.1 可靠性反模式

这些是规范示例，不是捏造的用户负评；不能承诺避免这些错误就提高平台评分。

| 反模式 | 正确边界 |
|---|---|
| 为了评分添加自动修复/自动重试选项 | 没有这些选项就是设计；失败只说明原因、影响、现状与下一步，等待新的明确授权 |
| 把“不自动修复”理解为不能首次生成或按需补文档 | 正常按证据生成、按确认事实补正文、用户新授权的新一轮操作均可；不能静默循环失败操作 |
| 未知对话参数照常忽略，top=99 改成 8 | 提示并问一个最小澄清；CLI 是另一层，未知/非法/多余参数严格拒绝 |
| 错键先删，可选文本 null 转空字符串 | 所有声明层级拒绝未知键，可选文本提供时严格 string；issues 指向字段，由执行者据证核对，不猜值 |
| 建议001 和建议 0001 当两个编号，或自动归并重排 | 识别空格/补零后的同号重复，停止，核对原编号映射，不自动改编号 |
| 非全文材料只填 state，或把失败材料移出数组 | 非全文必须非空 coverage，含已读/未读范围或失败原因；全部失败也逐条填写 |
| 页面只有折叠材料表提示“部分读取” | HTML 与 Markdown 开头显著 WARN-MAT-01 局部限定；不是全文通过，不改原判定函数 |
| 文档太大直接截掉后半部，用摘要代替正文 | 先目录/章节 manifest，再连续读取并记原位置、已读未读和跨章规则；读完才全文结论，无法完成列缺口 |
| 把 8 MiB 当源文件大小上限，或承诺固定页数/无限规模 | 上限只针对生成 DATA JSON；源文档受实际读取条件限制，不编造性能实测 |
| 显式 --format 覆盖时顺手改输入文件 | 先校验原 DATA，再只在输出嵌入副本记录生效格式，原对象/文件不改 |
| 双输出先写一个再检查另一个是否存在 | 所有目标统一预检；普通生成/六文件 demo 禁覆盖，父目录须存在，wx 单次写入并读回 |
| 写失败自动回退桌面、建目录、改名或删半成品 | 停止后续写入，保留文件，报告 completedFiles/incompleteFiles/unattemptedFiles/untouchedFiles，不称整体成功 |
| 把写入错误叫 ERR-OUT-02 | 写入为 ERR-OUT-05；OUT-02 保留模板缺项，读回为 OUT-04，预检 OUT-01，DATA OUT-03 |
| 运行 --templates 来覆盖任意旧报告 | 只用于授权维护两个固定 HTML 模板，不是普通输出覆盖开关 |
| 根据规则优先级直接忽略相互矛盾的实现 | 按 SKILL 路由/边界、review-core 字段/计算、build-review 写入、references 细则定位，冲突停相关环节，请维护确认 |
| 只把分数传给用例工具，待确认预期写成事实 | 保留 reportId/revision、原始标题、Q/建议、证据、未确认项与局部范围；真实执行另需环境授权 |
| 把“HTML 离线”说成读取在线材料也无需网络 | 模板/页面无外部依赖，本地读取可离线；企业微信文档、知识库等在线来源仍需网络和权限 |
| 假定下游技能一直安装、授权一直有效 | 当次核实工具与权限，不为组合演示向外上传真实例子 |
| 用历史 CHANGELOG 的旧参数行为当现行指令 | 历史不篡改；核对 v2.4.1 现行契约，仍有冲突先停，不自动忽略/收敛参数 |
| 把测试数量、Node 推荐或本地版本当作全面验证 | 两个测试脚本须实跑并记录；推荐 Node 22/24，本机版本 22.22.2，不声称跨平台全测或自动公开发布 |

## 5. 一页自查（交付前）

- 目标来自本轮，固定结论词、指数与 P0/P1 一致，没有选项串或推断冒充事实？
- 材料范围完整，未提供不等于不支持；部分/失败有 coverage，开头局部限定可见？
- 大文档台账含原位置、已读未读、跨章规则；未读完没有全文结论？
- DATA 无未知字段或类型松动，编号稳定，校验失败没有输出？
- 对话参数已澄清，CLI 参数严格合法，没有静默忽略或收敛？
- 输出目标预先确认、父目录存在，所有目标预检，普通输出不覆盖；未使用失败后换名或换目录？
- 已写文件实际读回，失败文件清单如实，不删除、不补写、不自动重试、不称整体成功？
- Markdown/HTML 同源、同 reportId/revision、同生效 format，输入文件未改？
- 确认/生成/写入/验证分开，默认未写入/未验证未被无依据升级？
- 规则冲突已停止相关环节，未擅自择一；错误信息无堆栈、无 JSON 原文片段？
- 示例虚构或脱敏，工具权限已核实，未向外上传真实例子；未声称评分提升？
