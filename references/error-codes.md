# 错误提示规范

材料读不到、格式异常、参数越界、落盘失败——**每一类异常都必须给出结构化提示，不得静默跳过，也不得含糊带过**。

---

## 1. 展示格式（固定三段式）

```
[ERR-XXXX] 一句话说明发生了什么
  · 已按规则处理：……（我做了什么兜底）
  · 建议你：……（下一步动作，要具体到可操作）
```

**硬要求**

| 要求 | 说明 |
|---|---|
| 码可识别 | 统一 `[ERR-模块-序号]`，用户能据此检索与反馈 |
| 三段齐全 | 缺任何一段都算不合格 |
| 一次汇总 | 多个异常在报告末尾集中列出，**不要每遇一个就打断一次** |
| 措辞委婉 | 沿用二级深审的措辞约束：不写"报错""失败""崩溃""无法继续"，写"未能读到""已按……处理" |
| 不甩锅 | 不写"你给的材料有问题"，写"这份材料我这边读到的是……" |
| 必须给下一步 | 每条都要有"建议你：……"，且是可执行动作 |

**正反例**

| 反例 | 正例 |
|---|---|
| 材料读取失败，无法继续 | `[ERR-MAT-01] 《XX方案》未能读到正文（知识库返回文件获取失败，已重试 2 次）`<br>`· 已按规则处理：在材料表标注读取状态，就已读部分出结论，未读部分不猜测`<br>`· 建议你：从知识库导出后给我文件路径，或直接粘贴正文` |
| 格式不支持 | `[ERR-MAT-02] 该文件解析后为空（.pages 格式暂不支持）`<br>`· 已按规则处理：跳过该文件，未据此下任何结论`<br>`· 建议你：另存为 docx / md / txt，或导出 PDF 后给我` |
| 参数不对 | `[ERR-PARAM-01] 未识别的参数「verbose」已被忽略`<br>`· 已按规则处理：其余参数照常生效，本次按默认配置执行`<br>`· 建议你：可用参数为 depth / lane / out / format / top / lang，见主文件 §2.5` |

## 2. 错误码清单

### 材料类（MAT）

| 码 | 触发 | 已按规则处理 | 建议你 |
|---|---|---|---|
| ERR-MAT-01 | 读取失败：路径不存在、无权限、知识库返回错误、下载中断 | 材料表标注读取状态；重读一次；就已读部分出结论，未读部分列入材料表 | 换导出件 / 给新路径 / 直接粘贴正文 |
| ERR-MAT-02 | 格式不支持或解析后为空 | 跳过该文件，不据此下任何结论 | 转 docx / md / txt / PDF，或提供截图 |
| ERR-MAT-03 | 需要登录、验证码或授权 | 停在受限位置，**不索取凭据、不用非官方接口绕过** | 导出可见内容，或提供已登录环境的截图 |
| ERR-MAT-04 | 多份材料版本冲突 | 并列各版本差异，请求指定 | 明确"以哪一版为准" |
| ERR-MAT-05 | 截图 / OCR 无法确认字段或数值 | 一律标"待确认"，不猜 | 提供更清晰的截图，或文字补充说明 |

### 路由类（ROUTE）

| 码 | 触发 | 已按规则处理 | 建议你 |
|---|---|---|---|
| ERR-ROUTE-01 | 未指定审查目标，材料也无明确动作信号 | 暂停，问一个最小问题（A/B/C/D） | 回复一个字母即可继续 |
| ERR-ROUTE-02 | 用户要求多角色评审但材料不足以支撑多条链路 | 只就已支撑的链路出结论，其余说明原因 | 补充对应材料后再要 |

### 参数类（PARAM）

| 码 | 触发 | 已按规则处理 | 建议你 |
|---|---|---|---|
| ERR-PARAM-01 | 出现未识别的参数 | 忽略该参数，其余照常生效 | 核对可用参数清单（主文件 §2.5） |
| ERR-PARAM-02 | 参数值越界（如 `top=99`、`depth=3`） | 按上限或最接近的合法值处理，并说明实际取值 | 调整到合法范围 |
| ERR-PARAM-03 | 参数互斥或自相矛盾（如 `format=md` 又要雷达图） | 以保守方案执行（保留 Markdown），说明取舍 | 明确优先级 |

### 输出类（OUT）

| 码 | 触发 | 已按规则处理 | 建议你 |
|---|---|---|---|
| ERR-OUT-01 | 落盘目录不可写或不存在 | 回退到桌面，并说明实际落盘位置 | 如必须落到指定目录，确认权限后重试 |
| ERR-OUT-02 | 模板字段无内容可填 | 填"待确认（材料未给出）"，**不许留空、不许编造** | 补充对应信息 |
| ERR-OUT-03 | HTML 的 `DATA` 区填充不完整 | 不输出半成品 HTML，先补齐 | 补充缺失字段 |

### 门禁类（GATE）

| 码 | 触发 | 已按规则处理 | 建议你 |
|---|---|---|---|
| ERR-GATE-01 | 自检 gate 未通过 | **不交付**，改到通过为止 | 按未通过项修改 |
| ERR-CONS-01 | Markdown 与 HTML 两处结论不一致 | 以 Markdown 为准，同步修正 HTML 后重新落盘 | 无需动作，我已在交付前处理 |

## 3. 三条易犯的错

| 坑 | 正确做法 |
|---|---|
| 遇到异常就沉默跳过，用户以为都读到了 | 必须出 `[ERR-…]`，并在材料表标注读取状态 |
| 只说"失败了"不给下一步 | 三段式最后一段必须给可执行建议 |
| 一次性报错刷屏，打断正常流程 | 异常在报告末尾"材料与执行提示"一节集中列出，正文该出结论照出 |
