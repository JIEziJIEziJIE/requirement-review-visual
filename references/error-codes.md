# 错误提示与失败边界（v2.4.1）

材料读不到、格式异常、参数非法、落盘失败都必须说明原因、影响和下一步。**没有自动修复或自动重试选项是设计约束。** 停止受影响环节，不静默跳过、不猜值、不把部分产物说成整体成功。

## 1. 两层提示格式

### 1.1 对话：固定三段式

```text
[ERR-模块-序号] 发生了什么，以及影响范围
  · 已按规则处理：实际已做或已停止的动作；是否有部分产物
  · 建议你：一个可执行的下一步；需要确认时问一个最小问题
```

- 影响可靠性、无法读取或无法生成的提示放开头；其它提示集中列出，不刷屏。
- “已处理”只能描述实际状态，不暗示已经修好。文件状态未知就写未知，不称未写入或已完成。
- 未知、非法、矛盾的**对话参数**必须提示并问一个最小澄清；不忽略、不夹取上限、不自行择一执行。
- 本轮出错后不自动修复或再次尝试。用户确认材料、路径或处理方案并新授权后，才可发起新一轮操作；不把这说成已执行的重试。
- 正常首次按证据生成、用户按需补文档不属于自动修复；被审查业务本身的重试/恢复逻辑仍是审查维度。

示例（全部虚构，不是实际执行记录）：

```text
[ERR-MAT-01] 《会议室预约 v1》正文未能读取，本轮没有可审查正文。
  · 已按规则处理：标记读取失败和失败原因；停止正常评分，未自动修复、未重试，未生成文件。
  · 建议你：请提供该版本的可读导出件或正文。

[ERR-PARAM-02] top=99 不在 1～8 的整数范围，首屏参数尚未确定。
  · 已按规则处理：暂停受影响的生成步骤，未将 99 自动改为 8。
  · 建议你：本次 top 要设为 1～8 中的哪个整数？

[ERR-PARAM-01] 未识别 verbose，尚不清楚预期效果。
  · 已按规则处理：未忽略该参数，暂停受影响步骤。
  · 建议你：verbose 在本轮希望控制什么输出？
```

### 1.2 生成 CLI：stderr 结构化 JSON

CLI 严格解析自己的语法，不进行对话澄清，也不接受所有对话参数。失败退出时 stderr JSON 含 `code`、`message`、`handled`、`next`、`details`（并带 `ok:false`）；不输出堆栈、不回显 JSON 原文片段。字段问题通过 `details.issues` 的 `code/path/message` 定位；普通使用者只需补业务事实，不需要手写 JSON。

以下是字段类型错误的格式示例，不是一次实测输出：

```json
{
  "ok": false,
  "code": "ERR-OUT-03",
  "message": "审查 DATA 不符合契约，未生成报告。",
  "handled": "未自动修复、未重试；未写入任何输出，无部分文件；未修改输入文件。",
  "next": "由执行者依据原材料核对 issues 指向字段；用户无需手写 JSON。",
  "details": {
    "issues": [
      {
        "code": "ERR-OUT-03",
        "path": "$.checks[0].advice",
        "message": "advice 必须为字符串"
      }
    ],
    "completedFiles": [],
    "incompleteFiles": [],
    "unattemptedFiles": []
  }
}
```

## 2. CLI 错误码与退出码

| 退出码 | 含义 | 错误码 |
|---|---|---|
| 0 | 命令成功；包括只读检查和单独帮助调用 | 无错误码；不等于需求业务通过或功能已验证 |
| 2 | 命令/参数非法 | ERR-CLI-01 |
| 3 | DATA JSON 输入读取、大小、编码或语法错误 | ERR-IN-01～05 |
| 4 | DATA 结构/一致性不符合契约 | ERR-OUT-03 |
| 5 | 输出预检、写入或读回失败 | ERR-OUT-01 / 04 / 05 |
| 6 | 未预期内部错误 | ERR-INT-01 |

| 码 | 触发 | 处理边界与下一步 |
|---|---|---|
| ERR-CLI-01 | 未知选项、缺失/多余参数、非法格式值、冲突或重复选项组合 | 严格拒绝、不写文件；执行者核对 `--help`，不忽略或自动改参数 |
| ERR-IN-01 | 路径不可读、不是普通文件、读取权限或读取失败 | 停止；执行者核对路径与权限，不改输入 |
| ERR-IN-02 | 统一审查 DATA JSON 大于 8 MiB | 停止；核对 DATA 组织与大小，不自动截断、压缩证据或拆分原材料；不是原始文档容量限制 |
| ERR-IN-03 | 非严格有效 UTF-8 | 不替换非法字节；执行者确认编码后准备有效 UTF-8 无 BOM 副本 |
| ERR-IN-04 | UTF-8 BOM | 明确拒绝，不自动去 BOM；执行者确认后准备无 BOM 副本 |
| ERR-IN-05 | JSON 语法错误 | 停止，不回显解析器原文片段；执行者核对语法，不自动补括号、引号等 |
| ERR-OUT-01 | 任一输出目标预检未通过，如父目录缺失、目标已存在、目标与输入冲突、名称非法 | 所有目标均不开始写入；核对目标，不回退桌面、不建目录、不改名 |
| ERR-OUT-03 | DATA 未知字段、类型、必填、编号、覆盖范围或状态关联错误 | 校验失败不生成；查看 issues 指向字段，依据原材料确认，不静默丢弃拼错键或猜值 |
| ERR-OUT-04 | 输出读回失败或内容不一致 | 停止后续写入，保留文件；不能把未验证文件记作完成，核对文件清单 |
| ERR-OUT-05 | 输出创建、写入或关闭阶段失败 | 停止后续写入，保留部分文件，不删除、不再次尝试；核对文件清单 |
| ERR-INT-01 | 未预期内部错误 | 停止，使用脱敏数据核对版本和调用；不输出堆栈或原始异常内容，不把既有产物状态笼统称成功 |

**编号不可复用**：`ERR-OUT-02` 保留给下节的“模板缺项”对话提示；不是写入错误。写入错误使用 `ERR-OUT-05`。

## 3. 文件清单与非事务写入

普通生成与 `--demo` 先统一预检全部目标，父目录必须预先存在；随后使用 `wx` 独占创建，每个目标执行单次写入和读回。预检不能保证之后 I/O 一定成功；即使预检后目标被其它进程创建，也拒绝覆盖。

I/O 中途失败在 `details` 中报告：

| 字段 | 含义 | 不得误称 |
|---|---|---|
| completedFiles | 已写完并读回一致的文件 | 不能由此称整个命令成功 |
| incompleteFiles | 已创建/已开始写入，但为空、截断或未通过读回核验的文件 | 不能当可交付完成品，也不能断言一定截断 |
| unattemptedFiles | 因停止而尚未尝试的后续目标 | 不能称已创建；预检失败时可列全部计划目标 |
| untouchedFiles | 当前失败发生在成功打开/创建之前、未由本轮触碰的目标 | 不等于路径不存在，可能有其它来源的同名文件 |

这是**非事务性输出**，不保证多文件原子提交或失败自动回滚。失败后不删除、不补写、不重跑、不换目录、不创建目录、不改名。让用户看到实际清单，由执行者核对证据；新一轮操作需要新的明确授权。

`--templates` 是唯一明确的维护覆盖例外：仅覆盖 `templates/fast-screen-card.html` 与 `templates/deep-review-radar.html` 两个固定模板，仍统一预检、单次写入并读回，失败保留现场；不是对任意文件开放覆盖。`--demo` 的六个目标必须一起预检，禁止覆盖。`--check` 和帮助命令不写文件。

## 4. 对话与材料提示码

以下为审查对话的提示规范，不把每个码都宣称为 CLI 退出错误。HTML/Markdown 中的材料提示也不表示 CLI 语法错误。

### 材料与范围

| 码 | 触发 | 已按规则处理 | 下一步 |
|---|---|---|---|
| ERR-MAT-01 | 路径、权限、知识库或读取环节失败 | 记录 state/coverage；不重读；全不可读停止正常评分，有可读范围则仅局部审查 | 提供可读导出件、正文或确认新的合法读取途径 |
| ERR-MAT-02 | 格式不支持或解析为空 | 不依据该文件下结论，不静默跳过 | 提供当前能力支持的导出件或正文 |
| ERR-MAT-03 | 登录、验证码或授权受限 | 停在受限位置，不索取凭据、不绕权限 | 按宿主流程授权或提供可读导出件 |
| ERR-MAT-04 | 多份材料版本冲突 | 并列来源与冲突，不默认一版正确 | 确认以哪一版为准 |
| ERR-MAT-05 | 截图/OCR 字段、数值或交互不清 | 保留待确认，不猜 | 提供清晰材料或文字确认 |
| WARN-MAT-01 | 部分可读：有可读材料且至少一份非“已读全文” | 计算结果带 limited/warnings；页面和 Markdown 开头显著限定局部审查，材料表列 coverage | 补足未读范围后另行审查，不能外推为全文通过 |

`coverage` 对“已读全文”可选；对“部分读取”与“读取失败”必须非空，描述已读/未读范围或失败原因。全部读取失败同样需要 coverage，不能只填状态。全不可读不出正常评分；部分可读只限定范围，不擅改原判定函数。

### 路由与对话参数

| 码 | 触发 | 已按规则处理 | 最小澄清 |
|---|---|---|---|
| ERR-ROUTE-01 | 目标不明 | 暂停目标判断 | A 提交评审 / B 开工 / C 初步可测 / D 完整深审，要哪项？ |
| ERR-ROUTE-02 | 多角色目标缺对应材料 | 只对有依据的范围判断，明确其它范围缺口 | 补充哪一目标的材料？ |
| ERR-PARAM-01 | 未知参数 | 不默默忽略，暂停受影响步骤 | 该参数希望控制什么？ |
| ERR-PARAM-02 | 非法值或越界，如 top=99、depth=3 | 不夹取边界或猜合法值 | 要使用哪个合法值？ |
| ERR-PARAM-03 | 参数或目标矛盾，如仅 Markdown 又要求交付 HTML 雷达图 | 不自行选择保守方案 | 本轮以哪种交付要求为准？ |

### 模板、门禁、一致性与后续操作

| 码 | 触发 | 已按规则处理 | 下一步 |
|---|---|---|---|
| ERR-OUT-02 | 审查正文模板缺少可填依据 | 如实标明待确认，不编造；必需 DATA 字段缺失仍阻断生成 | 由执行者定位缺口，请用户仅确认业务事实 |
| ERR-GATE-01 | 交付自检未通过 | 停止相关交付并列明未通过项，不自动修改至通过 | 先确认原因与处理范围，再决定是否授权新一轮操作 |
| ERR-CONS-01 | Markdown/HTML、规则文本与实现存在冲突 | 停止受影响结论或交付，保留原材料与 DATA；不默认一份一定正确 | 由维护者核对职责层与版本，确认处理方案后再操作 |
| ERR-ANS-01 | 回填缺原报告、编号映射或原文 | 不猜编号、不关闭事项 | 补必要材料 |
| ERR-ANS-02 | 答案含糊、冲突或缺来源 | 保持待确认，不自动改分 | 确认业务/研发各自答案与实际来源 |
| ERR-EDIT-01 | 编辑未授权、无权限、版本冲突或保存读回未完成 | 停止写入分支，不称已写入；已产生的文件如实列明，不自动清理 | 确认目标版本和新操作范围，或采用可粘贴正文 |

## 5. 交付前核对

- 提示与真实发生的动作一致，未写“已经修复”或“整体成功”掩盖失败。
- 参数澄清与 CLI 严格拒绝分层清楚，未自动忽略或收敛参数。
- 已知文件状态全部列出，保留部分文件，不删除或再次写入。
- DATA 错误定位到字段，不回显原始 JSON 片段或堆栈。
- 规则按 SKILL 路由/边界、review-core 字段/计算、build-review 写入、references 细则分工；检测冲突停止相关环节，不擅自择一。
- 历史 CHANGELOG 只记录当时行为，不作为现行失败处理指令；以 v2.4.1 契约核对，仍有冲突则先停下。
