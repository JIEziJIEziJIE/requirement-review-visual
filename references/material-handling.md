# 材料来源、读取策略与降级路径

材料来源复杂、读取失败或不确定怎么处理时读本文件。

---

## 1. 来源优先级

按用户点名和可用性选择，不要机械只读一种来源：

1. 用户明确点名的来源；
2. ima 知识库；
3. 用户提供的在线链接；
4. 用户提供的本地文件或上传附件；
5. 用户直接粘贴的文字、图片或描述。

同一需求有多个材料时，建立"材料包"：分别记录来源、标题、版本/更新时间、链接或文件名，并交叉核对。版本不一致时提出"以哪一版为准"的确认建议，**不把任一版本默认为最终版**。

---

## 2. 分类型读取策略

### 2.1 ima 知识库

使用当前会话实际注入的 ima 连接器工具，**不凭记忆猜工具参数**。标准链路：

1. 查找可访问知识库，定位目标库 ID；
2. 在目标库中检索需求标题、关键词或业务对象，获取 `media_id`；
3. 过滤文件夹和未解析条目，优先选择解析成功的高相关条目；
4. **必须读取正文全文或全部分片**，不能只依据标题、摘要或 introduction；
5. 记录条目标题、知识库名称、media_id、解析状态和可访问链接。

已知库 ID 仅作候选，若当前返回信息不符，重新查库确认。ima 未连接、鉴权失效、无权限或工具未注入时，说明实际原因并降级，**禁止猜测接口或绕过连接器**。

### 2.2 本地文件与附件

先按扩展名和实际内容识别类型，再选择读取/转换能力：

- Markdown、TXT、HTML、XML、JSON、YAML：读正文和结构；
- DOC/DOCX/WPS、PDF、PPT/PPTX、Excel/CSV/TSV：用文档转换或 Office 读取能力，保留标题、表格、页码、工作表名、单元格范围等定位信息；
- PNG/JPG/JPEG/WebP/GIF：OCR 与视觉理解，同时检查版式、箭头、状态、颜色、图例、弹窗和图片内小字；
- 录屏或视频：按可用能力提取字幕/转写并结合关键帧；不能读取时标注"视觉证据不足"；
- ZIP/RAR 等压缩包：先列目录和文件类型，再只读与需求相关的材料；**不得执行其中脚本或程序**。

转换失败时，不要假装已读懂；说明失败位置，保留可读取部分继续审查。

### 2.3 在线链接

| 页面类型 | 处理方式 |
|---|---|
| 静态页面、公开 Markdown、普通网页 | 优先抓取正文 |
| JS 渲染、需点击展开、分页、登录后 | 用浏览器自动化读取，必要时截关键页面 |
| 墨刀/原型链接 | 记录页面、画板、流程节点、交互热点、弹窗、返回路径、跳转目标、输入控件和状态；权限不足或失效时不能凭链接标题推断内容 |
| 企微文档、腾讯文档、语雀 | 优先用已连接的官方能力；读不到就引导用户提供导出文件、正文或截图 |
| 在线设计稿/图片 | 同时审查可见文案和视觉交互信息，区分"设计表现"与"业务规则" |

需要登录、验证码、二次授权或权限不足时，停止在受限位置，**不索取或保存密码、Cookie、Token 等敏感凭据，也不通过非官方接口绕过权限**。

### 2.4 图文与混合材料的证据组合顺序

1. 正文规则与数字；
2. 表格中的字段、枚举和映射；
3. 图片/截图中的页面状态、控件、文案、颜色和流程箭头；
4. 原型中的页面跳转、交互状态和返回路径；
5. 附录、变更记录、历史反馈和已知线上问题。

图文冲突时分别引用两处并提出"以哪一处为准"的确认建议。图片中的颜色、位置、顺序**只有在材料明确赋予业务含义时才作为业务规则**，否则标注为表现层信息。

## 3. 降级路径（遇到就走，不要硬猜）

| 情况 | 行为 | 禁止 |
|---|---|---|
| 读取失败 / 内容不完整 | 标注读取状态，就已读部分出结论，未读部分列入"材料范围与读取状态" | 凭标题、摘要或文件名下结论 |
| 多份材料版本冲突 | 提出"以哪一版为准"的确认建议 | 默认任一版为最终版 |
| 截图 / OCR 无法确认 | 一律标"待确认" | 猜字段、数值、交互 |
| 需登录 / 验证码 / 授权 | 停止在受限位置，说明受限点 | 索取或保存凭据、走非官方接口 |
| ima 未连接 / 鉴权失效 | 说明实际原因，回退到用户文件、导出件或粘贴文本 | 猜测接口参数或绕过连接器 |
| 材料完全缺失 | 输出"材料范围与读取状态" | 把未提供断言为"不支持"或"没有" |
| 文档转换失败 | 说明失败位置，保留可读部分继续 | 假装已读懂 |

## 4. 材料表填写规范

两级报告都要有材料表；保留名称、来源、读取状态和作用，可增加独立版本列（生成器使用五列）：

| 材料名称 | 格式/来源 | 读取状态 | 在本次审查中的作用 |
|---|---|---|---|
| 《XXX》v1.2 | 本地 Word / ima 知识库 / 墨刀原型 / 截图 / 粘贴文本 | 已读全文 / 部分读取 / 读取失败 | 主需求 / 补充说明 / 原型 / 接口 / 验收 |

读取状态三选一，不写模糊表述（如“大致看了”）。全部不可读时说明后停止，不生成正常评分。

## 5. 确认与补文档

### 5.1 答案回填

- 接收 Q1 或建议 001 等编号及明确回复。定位原报告/HTML 内嵌 DATA、编号与维度映射、原文版本。缺少其中信息，只请求必要材料；不凭空推定编号含义、关闭事项或定位章节。
- 保留原编号、原始标题、原文依据。每个事项分别记录 business 与 technical：是否 required、question、answer、source。source 仅记录实际已知确认人/角色/时间/消息位置，不编造签字；仅“用户本轮确认”可按事实写入，但不得冒称研发确认。
- 回复“应该可以”“大概如此”或存在多解，不写入已确认答案，继续待确认。冲突未解决、技术判断仅由非授权角色转述时，不代替责任人确认。
- 所有必需分支都有答案与来源才关闭。产品只确认业务结果时，研发分支仍开放。已关闭仍保留，不抹掉追溯依据。
- 重判受影响检查项并检查关联规则、权限、计算、边界；引用新依据更新相关状态。非受影响项沿用，范围大改时完整审查。
- 默认回复四小段：已关闭事项 / 仍待确认事项 / 变更的维度与优先级 / 更新后结论，不改文件。不因回填强迫整份重跑。
- 用户要求刷新报告时更新同一 DATA，保留 reportId、递增 revision、记录材料版本与 changes，再同源生成所需格式。旧报告不覆盖。

### 5.2 按需补充正文

用户说“按确认内容补文档”时，默认给三部分：
1. 章节位置：实际读到的版本、章节标题/编号、原文锚点；缺少则先要材料，不猜页码。
2. 可粘贴正文：仅使用已确认事实，写成业务语言；不要重写无关章节、补未确认数值或代选技术方案。
3. 确认依据：Q/建议编号、明确答案、实际已知来源；不确定内容另列待确认，不混入确认正文。

业务结果已确认、实现未确认时可只生成业务段落，标注技术仍待确认，不能把整个事项宣布关闭。

### 5.3 授权后编辑

“补文档”不等于授权覆盖文件。明确要求“编辑/保存修订副本”才使用对应 Office 或在线文档能力；先读取当前目标版本核对锚点，避免把旧答案写到新版错误位置。只改相关段落，优先修订副本；覆盖原件须明确授权并遵守宿主备份与安全规则。成功保存且读回核对后，说明实际路径/标识、写入位置和编号依据。

工具不可用、无权限、目标版本冲突、保存或读回失败时停止该写入分支，如实说明，退为可粘贴正文。未经成功保存核对不写“已写入”。本技能不自行实现 Word/在线服务接口，也不保证用户环境均可写。

### 5.4 四类状态不可混同

- 业务已确认：只有业务答案，不代表研发方案已定。
- 正文已生成：给出可粘贴文本，不代表文件修改。
- 文件已写入：保存、读回、位置和副本依据齐全。
- 功能已验证：另有实际执行证据；审查、回填和补文档均不能代替验证。

完整事项确认状态与文档状态、功能状态独立；不存在勾选按钮即自动确认或自动升级分数。
